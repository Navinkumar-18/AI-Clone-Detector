# VoiceGuard — Demo Dataset and Test Fixtures

## 1. Overview

VoiceGuard uses a two-tiered evaluation and demonstration strategy:
1. **Standardized Benchmarks**: ASVspoof 2019 Logical Access (LA) evaluation corpus for reproducible ML evaluation.
2. **Deterministic Test Fixtures**: In-memory synthetic audio fixtures used by the 54-test automated verification suite for repeatable regression testing.

---

## 2. Standardized Benchmark Dataset (ASVspoof 2019 LA)

### Dataset Structure:
```
data/
└── asvspoof2019LA/
    └── LA/
        ├── ASVspoof2019_LA_cm_protocols/
        │   ├── ASVspoof2019.LA.cm.train.trn.txt
        │   ├── ASVspoof2019.LA.cm.dev.trl.txt
        │   └── ASVspoof2019.LA.cm.eval.trl.txt
        ├── ASVspoof2019_LA_train/flac/
        ├── ASVspoof2019_LA_dev/flac/
        └── ASVspoof2019_LA_eval/flac/
```

### Protocol & Evaluated Subset:
- **Production Evaluation Script**: `evaluation/run_production_evaluation.py`
- **Evaluated Subset**: 250 clips (50 bona-fide human speech samples, 200 spoof synthetic speech samples generated by TTS/VC algorithms A07–A19).
- **Audio Format**: 16-bit FLAC / WAV, 16 kHz sample rate, single channel mono.
- **Results Artifact**: `evaluation/results.json`

### Evaluation Commands:
```bash
# Full evaluation on configured dataset
python evaluation/run_production_evaluation.py --data_dir ./data/asvspoof2019LA

# Smoke test evaluation (first 50 clips)
python evaluation/run_production_evaluation.py --data_dir ./data/asvspoof2019LA --max_clips 50
```

> **Dataset Missing Behavior**:  
> If the dataset is not detected at `--data_dir`, the script prints:  
> `NOT AVAILABLE — the dataset was not present at the expected path.`  
> It exits cleanly without fabricating metrics or crashing.

## 3. Synthetic Test Fixtures (`tests/conftest.py`)

For automated unit testing and CI/CD pipelines without downloading multi-gigabyte datasets, VoiceGuard provides mathematically generated, reproducible audio fixtures:

| Fixture Name | Characteristics | Purpose in Test Suite |
| :--- | :--- | :--- |
| `silence_audio` | 2.0 seconds of digital zeros ($\text{amplitude} = 0.0$) | Verifies that silence triggers `INSUFFICIENT_EVIDENCE` and never returns `bonafide`. |
| `empty_audio` | 0 samples (empty NumPy array) | Verifies boundary condition handling on empty audio inputs. |
| `short_audio` | 0.1 seconds of 440 Hz sinusoidal wave | Verifies that audio under `minimum_duration_seconds` is rejected safely. |
| `normal_audio` | 3.0 seconds of 440 Hz tone + low Gaussian noise | Speech-like signal verifying standard feature extraction and non-blocking inference. |
| `high_energy_audio` | 3.0 seconds of 880 Hz harmonic tone | Simulates elevated energy acoustic signals. |
| `clipped_audio` | 3.0 seconds of saturated waveform clipped at $[-1.0, 1.0]$ | Verifies clipping ratio detection in `audio_quality.py`. |
| `noise_only_audio` | 3.0 seconds of zero-mean Gaussian noise | Verifies voiced frame ratio heuristic behavior on unvoiced noise. |
| `corrupted_wav_bytes` | Random byte sequence with invalid RIFF headers | Verifies HTTP 422 Unprocessable Entity error handling. |

## 4. Controlled Demo Samples (`audio_samples/`)

The repository includes curated demo audio samples in `audio_samples/` for live hackathon judge presentations:
- `genuine_sample.wav`: Clean human speech sample for demonstrating the `LOW_RISK` / `ALLOW WITH CAUTION` flow.
- `spoof_sample.wav`: Synthetic cloned speech sample for demonstrating the `VERIFICATION_REQUIRED` and `ACTION_HELD` step-up flow.
